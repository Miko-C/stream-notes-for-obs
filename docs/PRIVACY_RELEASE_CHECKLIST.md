# 公開者向けプライバシーチェックリスト

Stream NotesをGitHubやBOOTHへ公開・更新するときの確認項目です。

## 公開物へ入れないもの

- `%LOCALAPPDATA%\StreamNotes\state.json`やプロジェクト内の`data/`
- 配信原稿、読み上げメモ、調査資料、未公開企画
- `.env`、APIキー、アクセストークン、Cookie、パスワード
- OBSの配信キー、YouTubeやTwitchなどの認証情報
- DiscordなどのWebhook URL、非公開サーバーや管理画面のURL
- 秘密鍵、コード署名証明書、復旧コード
- ログ、PID、クラッシュダンプ、ブラウザーのプロファイル
- 本名、住所、電話番号、非公開メールアドレス、口座情報
- `C:\Users\名前`など、利用者名を含む絶対パス
- 非公開リポジトリ名、顧客名、共同制作者の個人情報
- 元画像の位置情報、撮影者名、端末名などのメタデータ

## スクリーンショットと動画

- デスクトップ、通知、タブ名、ブックマークを写さない
- OBSの配信キーや限定公開URLを写さない
- サンプル文書だけを表示し、実際の配信原稿を使わない
- 公開前に画像メタデータとファイル名を確認する
- 音声入り動画では通知音や周囲の会話も確認する

## GitHub公開前

- `git status --short`で未追跡ファイルを確認する
- `.gitignore`に`data/`、`output/`、`release/`、`tmp/`、ログ、PIDが含まれることを確認する
- Git履歴の作者名とメールアドレスが公開用情報になっていることを確認する
- `.env`や秘密情報を一度でもコミットした場合は、削除コミットだけで済ませず、その認証情報を失効・再発行する
- 公開リポジトリへプッシュする前にZIPとソースの両方を検索する

## BOOTH公開前

- 配布ZIPを新しいフォルダーへ展開し、起動と終了を確認する
- ZIP内に`state.json`、原稿、ログ、PID、`.env`がないことを確認する
- ZIPのSHA256を計算し、商品ページかGitHub Releaseへ掲載する
- ウイルス対策ソフトでZIPを検査する
- 商品説明やPDFに非公開の連絡先や個人用URLがないことを確認する

秘密情報が見つかった場合は公開を止め、ファイルの除外だけでなく、該当するキーやパスワードの失効・再発行まで行ってください。
